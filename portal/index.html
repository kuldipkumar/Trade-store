Every trade version checked, stored and audited, from stream to report.

The Trade Store takes trades from a Kafka stream and a REST API, enforces the version and maturity rules, expires matured trades every night, and keeps an append-only audit of every outcome. This page follows the work from the business requirement to the running system; every card opens the real document, test, pipeline run or report.

5 · Two stores, one consistent record

Database design

PostgreSQL is the system of record for the latest version of each trade. MongoDB keeps the append-only audit trail and the version history. The transactional outbox ties them together, so a stored trade is never left unaudited (ADR-005). Tables and indexes below are read from the Flyway migrations and the MongoDB adapters themselves.

9 · Run and operate

Observability dashboard

Metrics (Prometheus), traces (Tempo) and logs (Loki), linked by trace ID in one Grafana dashboard. Every trade is one trace: the Kafka message, ingestion, each PostgreSQL statement, and about a second later the outbox relay's MongoDB writes. Every log line carries its trace ID. Readiness is UP only when PostgreSQL, MongoDB and Kafka are reachable.
