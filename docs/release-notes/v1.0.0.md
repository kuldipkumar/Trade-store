# Trade Store v1.0.0

Released 2026-11-28 · [Portal](https://kuldipkumar.github.io/Trade-store/) · [API reference](https://kuldipkumar.github.io/Trade-store/api.html) · [Source](https://github.com/kuldipkumar/Trade-store) · MIT licence

The first public release of the Trade Store: a Spring Boot service that ingests trades from a Kafka stream and a REST API, enforces the version and maturity rules, expires matured trades, and keeps an append-only audit trail of every outcome. Built test-first to the [assignment](../../Requirements.md), with every acceptance criterion traced to its tests.

## What it does

| Rule (from the brief) | Behaviour | Proof |
|---|---|---|
| Lower version | Rejected with `LowerVersionException`; REST 409; audited `REJECTED` (`LOWER_VERSION`) | US-104, US-106 (concurrent writes) |
| Same version | Replaces the stored record; REST 200; audited `REPLACED` | US-103 |
| Maturity before today | Rejected; REST 422; audited `REJECTED` (`MATURITY_IN_PAST`). Equal to today is accepted. "Today" is in the configured time zone. | US-201, US-205 |
| Maturity passed | Marked `expired = Y` by a daily job (00:05, plus catch-up at startup); audited `EXPIRED` | US-202 to US-204 |

The brief's sample table is reproduced as an end-to-end test (`AssignmentScenarioIT`).

**Channels.** Kafka `trades.inbound` (6 partitions, keyed by `tradeId` so a trade's versions stay in order) and `POST /trades`. Both run the same ingestion use case. Reads: `GET /trades`, `GET /trades/{id}`, `GET /trades/{id}/history`, and `GET /reports/audit` as JSON or streamed CSV.

**Stores.**
- **PostgreSQL** is the system of record: the latest version of each trade, written with a version-guarded upsert.
- **MongoDB** holds the trade history and the audit trail. Audit entries are written through a **transactional outbox** (ADR-005), so a stored trade is never left unaudited, even while MongoDB is down.

**Failure handling.**
- Unreadable messages go straight to the dead-letter topic `trades.inbound.DLT` (as `POISON`).
- A database outage is waited out and never dead-letters a trade (decision D9).
- Other persistent failures are retried 3 times, then dead-lettered as `FAILED`.

## Fixed in v1.0.0 (found by the release audit)

| Issue | Before | Now |
|---|---|---|
| A trade ID over 64 characters, or containing NUL | Passed validation, then failed in PostgreSQL: REST **500** with the rejection's audit entry lost; on the stream, 3 retries and a `FAILED` dead letter | Final `INVALID_FIELD` rejection (400). Audited without a `tradeId`; the raw payload is kept (A-55). |
| An ID with an unpaired Unicode surrogate | Stored as `?`, so two different IDs could collide and one replace the other | Rejected as `INVALID_FIELD` |
| A rejected ID with CR/LF | Written raw to the outcome log line, so log lines could be forged | Logged and traced as `<invalid>` |
| A malformed query string (`GET /trades?=&page=0`) | 500 | 400 `INVALID_PARAMETER` |
| `lz4-java` 1.11.2, `snappy-java` 1.1.10.7 (via `kafka-clients`) | 3 HIGH CVEs | Pinned to 1.11.4 and 1.1.10.9 |
| Two activity diagrams | Failed on PlantUML 1.2024.x | Render on 1.2024 and 1.2026 |
| Decision D10 on the portal | Missing | Listed |

Each fix was made test-first. The new acceptance tests fail on the previous code.

## Run it

```bash
git clone https://github.com/kuldipkumar/Trade-store.git && cd Trade-store
docker compose up --build -d                  # app, Kafka, PostgreSQL, MongoDB, Prometheus, Tempo, Loki, Grafana
python3 scripts/load_trades.py --rate 100     # stream the 10,000-trade file into Kafka
```

Then open:
- **API:** http://localhost:8080
- **Grafana:** http://localhost:3000, with the Trade Store dashboard of metrics, logs and traces.

Tests: `./mvnw verify` (needs JDK 21 and Docker).

## Known issues and limitations

- **Security controls are out of scope for this PoC** (decision D10): no authentication, authorisation or TLS, and a single instance. The scans still run on every change.
- **Open scan findings, none blocking:**
  - CVE-2026-118259 (MEDIUM) in `opentelemetry-api` 1.62.0, which Spring Boot manages; fixed upstream in 1.67.0.
  - ZAP Medium/Low header findings: no `X-Content-Type-Options` or site-isolation headers, and `/actuator/health` shows component status.
- **History and audit are eventually consistent:** an entry appears after the outbox relay runs, normally within a second.
- **Paging uses offset/skip**, which gets slower on deep pages.
- The CSV export is bounded by MongoDB's 10-minute idle-cursor timeout.
